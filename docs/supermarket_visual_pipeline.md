# VERDANT MARKET visual pipeline

## Purpose and research boundary

`HERO_SUPERMARKET` is a presentation digital twin for the Q3 research application. It provides a realistic retail context for navigating the study and for explaining the near-expiry shelf-label workflow. Its RGB renders are not spectral measurements, printer measurements, reflectance data, or human-participant observations. The original controlled measurement scene is retained as `RESEARCH_LABEL_MEASUREMENT` in `blender/q3_supermarket.blend`; the source baseline remains `blender/q3_project.blend`.

Open `blender/q3_supermarket.blend` for the full supermarket; `q3_project.blend` is intentionally the compact controlled shelf fixture used for the twelve research renders. The saved supermarket startup view is the hero camera. The embedded `Q3 Lighting Lab.py` script registers an N-panel for switching the live presentation scene between L1, L2, and L3. Run it once from Blender's Scripting workspace, then use **N → Q3 Research** in the 3D View. The dashboard's WebGL scene updates its key, fill, ambient, spot, and point lights on the same selection, and the nearby three-image comparison uses the corresponding actual Blender RGB outputs.

The authoritative D65, neutral-LED approximation, and warm-LED approximation are the Python spectral distributions used by `colour_engine`. Blender cannot be treated as a spectral renderer in this pipeline. The hero scene uses deliberately differentiated neutral-cool, warm-neutral, and amber RGB presentation presets so the interaction is visible during a demonstration. Blackbody nodes remain on luminous presentation panels. These are visual teaching presets, not physical simulations of the defined SPDs, calibrated CCT outputs, or measured retail LED spectra. All twelve research comparisons and CIEDE2000 values continue to come from the existing scientific pipeline.

## Regeneration

Run from the repository root using the installed Blender executable:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b blender/q3_project.blend --python blender/scripts/build_supermarket.py
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b blender/q3_supermarket.blend --python blender/scripts/render_supermarket.py -- --preview
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b blender/q3_supermarket.blend --python blender/scripts/export_web_model.py
```

After reviewing proof frames, render the release set and make its comparison/contact sheets:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b blender/q3_supermarket.blend --python blender/scripts/render_supermarket.py
python blender/scripts/compose_supermarket_evidence.py
```

`render_supermarket.py -- --preview` creates 960×540, eight-sample review frames. The final pass produces the six named 2560×1440 PNGs, uses Cycles on CPU, OpenImageDenoise, and the AgX Medium High Contrast view. The fixed camera names and light conditions make the outputs repeatable. The three input frames to the illuminant plate are saved in `illumination_components/` for auditability. The contact sheet is `blender/renders/supermarket/supermarket_contact_sheet.png`.

## Scene construction

The builder scripts separate architectural shell, gondola fixtures, ticket assemblies, generated packaging, light rig, and locked cameras. The current build has four stocked aisles, a stone-tile floor, glazed entrance, oak joinery, produce island, chilled cases, checkout, a branded rear wall, and 608 linked product assemblies across 12 package families. Fictional VERDANT MARKET package graphics are generated by `blender/scripts/generate_packaging_art.py`; no scanned commercial labels or product photographs are used. Six camera outputs cover the whole market, shelf display, donate-now macro, four-state status rail, illuminant appearance comparison, and open-roof isometric view. The isometric render hides the ceiling and its diffuser meshes together while retaining the separate area-light rig, so the cutaway does not show floating fixtures.

Expiry label textures are rendered from original digital artwork, with the `R` card sourced from the configured `#D62828` graphics. Each Blender label panel stores its configured colour ID and sRGB hex in object metadata. Clear ticket windows, card stock, ticket cassettes, retaining clips, shelf channels, posts, and shelf decks are separate scene objects. The label artwork is still a synthetic RGB texture, not a measured paper or ink spectral-reflectance sample. The existing virtual-print model assumptions and limitations remain in `docs/model_assumptions.md`.

`blender/scripts/export_web_model.py` creates an 8–9 m linked-mesh featured shelf segment from `HERO_SUPERMARKET`, retains the `Q3_LABEL_G/Y/O/R_PANEL` object names for browser hit testing, and exports the compressed source asset to `frontend/public/assets/supermarket/verdant_market.glb`. It excludes the full store shell, camera rig, non-featured product rows, and the hidden source-template library. The React Three Fiber scene lazily loads this GLB; it is a visual control surface only and does not perform science calculations.

## Reproducibility metadata

The builder adds scene-level custom properties for the project name, configured warning hex, lighting interpretation, product families/count, rendering role, and source configuration. `config.json` is not edited by this visualization work. This separation keeps the original twelve research conditions and the computational evidence stable while adding a richer environment for the application.
